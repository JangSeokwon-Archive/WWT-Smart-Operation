# 엔지니어링 검토 요약

가장 큰 기술적 한계는 **실제 계측값의 이용 가능 시각과 모델 학습 출처를 독립적으로 입증하지 못해, 과거 정확도가 신규 현장에서도 유지되는지 알 수 없다는 점**이다. 지금까지 가장 확실하게 확인된 개선은 미래 데이터를 참조하던 전처리와 시간 정렬의 수정이다. 이는 테스트로 확인된 평가의 타당성 개선이지 실운전 정확도 개선 증명이 아니다. 과거 모델 간 상세 성능 비교는 비공개 보고서에서만 확인할 수 있으며 신규 현장 기간의 지속적 우위는 미확정이다. 후보 파일도 저장되지 않아 원본 모델을 다시 배포할 수 없다.

Delta, OOF 잔차 보정, regime/learned hybrid, 공정 lag와 경험적 conformal은 비교 또는 구현되었으나 현장 신규 기간에서 지속적 개선이나 안전한 경보 성능이 입증된 방법은 아니다. 통계적 lag를 실제 체류시간으로, 동시각 TOC 차이를 제거율로, feature 중요도를 인과효과로 해석해서는 안 된다.

모델은 유량×유입 농도의 부하 대용, 전처리·병렬 폭기조 차이, DO 지속시간, MLSS 장기 변화, 과거 TOC 추세를 반영하려 했다. 하지만 유량 단위, 장치 경로, 장비 상태와 실제 보고 지연은 확인되지 않았다. 다음 알고리즘보다 먼저 원천 채취·실제 보고·collector 수신 시각, timezone/시계 동기화, 센서 단위와 품질·점검·수정 이력, 공정 계통과 신규 독립 운전 기간을 확보해야 한다. 고부하·충격 사건 수와 운전자의 허용 오경보 및 대응시간도 필요하다.

다음 실험 하나는 **EXP-01 유입 변화 지연 feature**를 추천한다. 유입의 변화가 방류 예측에 선행 정보를 주는지 같은 모델·같은 원점에서 직접 검증할 수 있기 때문이다. 다만 실제 계측 시각·단위와 독립 잠금 기간이 확보되기 전에는 수행하지 않는다. 현장 적용은 여전히 보류하며 TOC 예측과 조작 효과의 인과 검증은 별개다.

| 기술적 문제 | 선택한 해결 방법 | 선택 근거 | 검증 결과 | 현재 판단 |
|---|---|---|---|---|
| 미래 입력 누수 | 지연 적용, 제한 forward fill, trailing 특성 | 발행 시점 정보만 사용 | 합성 prefix·정렬 테스트; 현장 지연은 미확인 | 유지 및 현장 확인 |
| 시간별 모델의 과대평가 | walk-forward와 시간 purge | 정답 보고 시각 경계 분리 | 코드·테스트 확인, 센서 지연은 가정 | 유지 |
| 안정 운전에서 ML 오차 | persistence+ML | 기준 예측과 변화 신호 절충 | 과거 비교 수행; 상세 결과 비공개, 불확실성 남음 | 추가 검증 |
| 급등 경보 은폐 | raw와 제한 예측 분리 | 단기와 장기 변화 차이 보존 | guard의 은폐 가능성 확인, 현장 성능 미검증 | 추가 검증 |
| 불확실한 점 예측 | 사전 잔차 conformal | 경험적 구간과 폭 제시 | 과거 persistence만 평가, 미래 보장 없음 | 추가 검증 |
| 사후 평가의 사전성 부족 | shadow 원장 | 예측·수신·스냅샷 이력 | 합성 테스트와 historical replay만 수행 | 실제 수집 필요 |
| 후보 모델 출처 불명 | 해시·시간·환경 manifest 검사 | 재현 및 독립 감사 준비 | 형식과 파일 무결성만 확인; 주장 사실성 미검증 | 배포 보류 |
| LLM 조작 권고 위험 | 근거 코드로 출력 제한 | 예측은 개입 인과가 아님 | 소프트웨어 제한; 운전자 평가 없음 | 유지 |
