# 배포 준비도

| 단계 | 현재 상태 | 확인된 근거 | 미충족 사유 |
|---|---|---|---|
| Level 1 연구용 | 부분 충족 | 예측 UI, 정렬·누수 테스트, 시계열 모델 비교, ADR | 과거 모델 출처와 정확한 원본 후보 재현 불가; 원본 센서 이용시각 미확인 |
| Level 2 shadow | 부분 구현, 검증 미완료 | 원장의 실시간 기록·사전 예측·도착 후 평가·persistence·경험적 calibration/drift 코드 | 실제 collector/신규 prospective 데이터 없음, 후보 출처·장비 시각 미검증, 자동 서비스 미구성 |
| Level 3 의사결정 지원 | 미충족 | 위험군 및 이벤트 평가 설계 | 독립 사건, 허용 오경보·선행시간, 설비 제약, 운전자 시험·현장 승인 부족 |

Level 3는 자동제어가 아니다. TOC 예측 정확도와 DO·반송량·인발량에 대한 개입 효과는 별도 문제이며 관찰적 중요도나 시뮬레이터가 조작의 인과효과를 증명하지 않는다. 배포 전 현장 목적에 맞게 정확도, 위험군, 신뢰구간 폭과 coverage, 이벤트 수·탐지·선행시간·오경보, 데이터 품질·중단 대응과 승인 책임을 사전 합의해야 한다. MAE 개선만으로 승인하지 않는다. 관련: `docs/OPERATIONAL_DATA_REQUIREMENTS.md`, `docs/V22_SHADOW_VALIDATION.md`, `docs/EXPERIMENT_BACKLOG.md`.

## 후보 재현 및 출처

V2.1 코드는 동일 데이터 해시와 환경·분할 조건으로 재실행할 수 있도록 되어 있으나 모든 의존성·환경과 과거 장비 이용시각이 보증되지 않는다. 원래 저장하지 않은 후보와 비트 단위 동일성을 확인하거나 원본을 복원했다고 주장할 수 없다. 재학습 시 새로운 ID·파일로 등록하고 기존 최종 테스트를 튜닝에 쓰지 않는다. 대상 이용 가능 최종 시각과 학습 시작/종료, 데이터 해시, feature/config, 파라미터, 전체 코드 commit, 패키지/환경, 모델 SHA, calibration 출처, 검증·승인 상태를 비공개로 보존한다. 종속성 잠금과 데이터 작성 시각, 외부 감사 근거가 있어야 독립 검증이 가능하다.

`wwt_toc_dashboard/core/model_provenance.py::validate_manifest`는 별도 private manifest의 필수 필드, 파일 SHA, 주장된 시간 순서와 issue 이전 생성을 확인하며 모델을 역직렬화하지 않는다. `training_start/end`는 학습 데이터 시간 범위, `training_run_started_at/completed_at`은 실행 시각이며 모든 정답이 실행 시작 전에 이용 가능하다는 보수적인 조건을 적용한다. 검증 상태와 승인 상태의 문자열은 주장일 뿐이며 반환값은 언제나 `claims_verified=false`, `deployment_authorized=false`다. 이는 shadow 발행에 통합된 승인 게이트가 아니며 원장의 기존 artifact 검사도 독립 출처 증명이 아니다. 학습 데이터 해시는 형식만 검사하며 실제 데이터와 일치하는지, 실제 정답 도착이나 학습 실행이 사실인지는 확인하지 않는다. 실제 후보 등록 및 배포는 별도 독립 검토가 필요하다. 모든 모델 파일은 신뢰된 출처에서만 로드한다.
