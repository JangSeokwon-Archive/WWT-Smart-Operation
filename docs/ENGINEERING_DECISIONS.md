# Engineering Decision Records: V1–V2.2

기록은 코드와 기존 보고서에서 확인한 사실을 기준으로 한다. 당시 의도가 명시되지 않은 가설은 **현재 코드에 근거한 추정**이다. 성능과 현장 시각 등 민감한 결과는 공개하지 않는다. 공정 해석은 현장 설계 확인 전 가설이다. 관련 커밋은 V1 `7510c77`, V2 `b405042`, V2.1 `eb98c3a`, V2.2 `0955140`이다.

#### Decision ID: ADR-001
**문제 상황**: 여러 공정 계측값으로 비선형 미래 TOC를 추정해야 한다.  
**공정·기술적 배경**: 유입, 처리 상태, 지연의 관계는 선형이라고 보장되지 않는다.  
**가설**: 트리 기반 LightGBM이 비선형과 결측을 처리할 수 있다. 최초 선택 의도는 **현재 코드에 근거한 추정**이다.  
**검토한 대안**: 실제 V2 비교는 persistence, seasonal naive, XGBoost 등; 신규 제안은 단순 선형 모델.  
**선택한 방법과 근거**: V1 번들 및 복구된 래퍼는 LightGBM을 사용한다. 최초 선정 당시 다른 근거는 확인되지 않았다.  
**기대 효과**: 비선형 예측과 표 형태 데이터의 효율적 학습.  
**검증 방법과 실제 결과**: V2는 동일 시점에서 기준 모델과 비교; 상세 결과는 비공개 보고서. 최초 모델의 학습 출처는 불명.  
**한계 및 반론**: 시간 외삽과 공정 변화에 취약할 수 있으며 중요도는 인과가 아니다.  
**현재 판단**: 추가 검증.  
**다음 행동**: 출처가 검증된 신규 후보를 독립 기간에 persistence와 비교.  
**근거**: `wwt_toc_dashboard/core/automl_infer.py`, `docs/V2_ENGINEERING.md`, `wwt_toc_dashboard/scripts/evaluate_v2.py`.

#### Decision ID: ADR-002
**문제 상황**: 단일 모델의 체계적 잔차를 줄일 필요가 있다.  
**공정·기술적 배경**: 공통 예측 패턴과 남은 비선형 오차는 다를 수 있다.  
**가설**: 기본 예측에 잔차 보정을 더하면 오류가 줄 수 있다. 과거 의도는 **현재 코드에 근거한 추정**.  
**검토한 대안**: 실제 직접 LightGBM, persistence, OOF 잔차; 신규 제안은 정규화 선형 보정.  
**선택한 방법과 근거**: V1 잔차 구조를 V2에서 purge된 OOF 예측으로 재평가한다.  
**기대 효과**: 기본 모델의 반복 오차 보정.  
**검증 방법과 실제 결과**: V1의 학습행 내 예측 잔차는 OOF가 아님이 코드에서 확인; V2 OOF 비교는 비공개.  
**한계 및 반론**: 잔차 모델도 과적합 가능, 과거 배포 모델 재현 불가.  
**현재 판단**: 추가 검증.  
**다음 행동**: 동일 데이터·동일 원점에서 직접 모델과 비교.  
**근거**: `wwt_toc_dashboard/core/forecast_training.py`, `docs/V2_ENGINEERING.md`.

#### Decision ID: ADR-003
**문제 상황**: 대응에 필요한 예측 선행시간이 서로 다르다.  
**공정·기술적 배경**: 긴 예측은 계획에 유용할 수 있지만 불확실성이 커질 수 있다.  
**가설**: 6/12/24시간별 모델 비교로 정확도와 선행시간의 차이를 드러낼 수 있다. 선정 의도는 **현재 코드에 근거한 추정**.  
**검토한 대안**: 실제 세 horizon 비교; 신규 제안은 현장 대응시간에 맞춘 다른 horizon.  
**선택한 방법과 근거**: 각 시점 +6/+12/+24시간의 표본을 각각 평가한다.  
**기대 효과**: 경보의 적시성과 정확도 분리.  
**검증 방법과 실제 결과**: 코드 및 horizon별 테스트가 정렬을 점검한다; 시간 선택의 현장 적합성은 미검증.  
**한계 및 반론**: horizon이 실제 수리 체류시간을 의미하지 않는다.  
**현재 판단**: 추가 검증.  
**다음 행동**: 운전자 대응시간과 비용에 따라 재설정.

#### Decision ID: ADR-004
**문제 상황**: 분석 지연을 예측 대상 시각에 더하면 명시한 horizon과 실제 대상이 달라진다.  
**공정·기술적 배경**: 채취와 분석 결과 이용 시각은 다르다.  
**가설**: 지연은 입력의 이용 가능성에 적용하고 정답은 정확히 origin+h로 정렬해야 한다.  
**검토한 대안**: 실제 V1 lead+delay 대 V2 분리; 신규 제안은 계측별 실제 도착 시각 적용.  
**선택한 방법과 근거**: V2 `make_labels`는 h만 이동하고 입력에는 별도 delay를 적용한다.  
**기대 효과**: 명시된 대상 시각과 정답의 일치, 미래 입력 차단.  
**검증 방법과 실제 결과**: 정렬 테스트; 기본 지연은 가정이며 현장 실측이 아니다.  
**한계 및 반론**: 고정 지연은 변동하는 실험실 지연을 표현하지 못한다.  
**현재 판단**: 추가 검증.  
**다음 행동**: 채취·보고 기록으로 센서별 이용 가능 시각 검증.

#### Decision ID: ADR-012

**공정·기술적 배경**: 시계열 잔차와 공정 분포는 변한다.

**현재 판단**: 추가 검증.

#### Decision ID: ADR-014
**문제 상황**: 사후 재현은 예측이 실제 정답보다 먼저 존재했는지 입증하지 못한다.  
**공정·기술적 배경**: 지연·수정·서비스 중단이 운영 기록에 영향을 준다.

**검토한 대안**: 실제 historical replay와 prospective 분리; 신규 제안은 외부 신뢰 시각·감사 앵커.  
**선택한 방법과 근거**: SQLite hash chain, 별도 무효화, 예측 후 정답 도착 시 평가.  
**기대 효과**: 누수 및 수정 이력 추적.  
**검증 방법과 실제 결과**: 합성 테스트 및 과거 replay만 수행; 실제 prospective는 미수집.  
**한계 및 반론**: 로컬 시계·원장·출처 주장은 외부 증명이 아니다.  
**현재 판단**: 추가 검증.  
**다음 행동**: 현장 collector, 시계 동기화, 외부 감사 구축.

#### Decision ID: ADR-015
**문제 상황**: LLM이 근거 없는 조작량·확률을 생성할 수 있다.  
**공정·기술적 배경**: 예측 연관성은 DO·반송·인발 조작 효과를 증명하지 않는다.  
**가설**: 결정적 근거 코드로 출력 범위를 제한하면 허위 조작 권고를 줄일 수 있다.  
**검토한 대안**: 실제 자유 문장 대신 조건 검증된 근거 코드; 신규 제안은 승인된 문구 검토.  
**선택한 방법과 근거**: 검증되지 않은 제어량·확신도는 배제하고 PLC 전송은 없다.  
**기대 효과**: 인과 미검증 조작 추천의 위험 감소.  
**검증 방법과 실제 결과**: 구현 및 테스트는 출력 제한을 점검; 실제 운전자 안전성 평가는 없다.  
**한계 및 반론**: 출력 제한만으로 화면 전체의 오해를 없앨 수 없다.  
**현재 판단**: 유지.  
**다음 행동**: 운전자 검토와 설비별 안전 제약 확보.
